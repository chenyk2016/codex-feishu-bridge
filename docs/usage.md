# 使用与排障

## 在飞书中操作

- 发「当前聊天」核对目标，再发任务。收到「已加入」后，到原桌面聊天确认执行。
- 发「菜单」或「切换聊天」选另一个已登记目标。引用有路由绑定的回复卡可继续卡片对应的聊天。
- 在本机设置页关闭「连接飞书」。页面保留，连接停止，恢复时跳过关闭前待发的旧汇报及关闭期间的消息。已提交给飞书的请求仍可能送达。

## 功能配置

所有设置写在运行目录中。直接编辑文件前先停止服务，保留 600 文件权限。修改 Codex 目标时使用新的运行目录，避免复用旧路由和去重状态。

| 需求 | 配置 |
| --- | --- |
| 多个指定聊天 | 在 `session-catalog.json` 的 `sessions` 追加聊天 ID、名称和实际工作目录。保留默认聊天 ID 与 `service.json` 一致。参考[示例](../examples/session-catalog.example.json) |
| 图片收发 | 初始化加 `--media`，或设置 `mediaEnabled`。设置可选的 `mediaAllowedRoots` 以批准具体输出目录。显式 Markdown 图片引用才会上传。当前每轮最多四张，每张 10 MiB |
| Mermaid | 启用图片，安装 Google Chrome。代码块离线渲染为 PNG；渲染失败时回复保留文字 |
| 全主聊天汇报 | 显式添加 `--all-local-reports --metadata-db 路径` 并安装 Stop Hook。公开范围包括本机主聊天中的最终回复。可将 `report-policy.json` 的 `enabled` 设为 `false` 撤回该范围 |
| 最近回复 | 加 `--recent-replies --metadata-db 路径`，成功汇报的聊天进入最近 10 个回复目标 |
| 新建聊天 | 实验功能。加 `--chat-management`，建议也提供 `--metadata-db`。在飞书发「新建聊天」，按卡片提示填写标题和首条任务。控制聊天须能用桌面聊天管理工具，且工作目录是已登记的 Codex 项目 |

聊天元数据使用当前桌面客户端内部 SQLite 结构，例如 `~/.codex/state_5.sqlite`。版本变化时可能失效。桥接对查询只读，限定为会话身份、名称、目录和归档状态。

## 排障

| 现象 | 核对 |
| --- | --- |
| 设置页打不开 | 确认 `foreground` 或登录服务正在运行，地址与端口正确。本机开关控制的是飞书长连接 |
| 已连但机器人收不到消息 | 核对应用发布、可用范围、事件订阅和应用是否还有另一长连接实例 |
| 能收文字，卡片点击无效 | 核对新版 `card.action.trigger` 的长连接回调已发布 |
| 入队后聊天没有动 | 打开正确的原桌面聊天，核对聊天 ID 与当前客户端。避免重复提交结果不明确的请求 |
| 飞书没有 Codex 回复 | 核对 Hook 路径、信任状态、聊天范围和设置页开关 |
| 图表只有文字 | 核对 Google Chrome、图片权限和 Mermaid 语法。图片目录还需匹配本机白名单 |

状态用 `/usr/bin/python3 manage.py status` 查看。私密诊断日志为运行目录的 `logs/connector.log`。向别人提供诊断前，先移除配对码、路径、聊天 ID 和正文。

## 运行数据与卸载

运行目录包含应用凭据、配对状态、待发回复、媒体缓存、去重记录和诊断日志。文件和目录仅由本机用户访问。回复和媒体缓存当前没有自动清理；需要整理时先停止服务，保留重要回执，避免因删除去重状态重发或重跑旧请求。

`/usr/bin/python3 manage.py uninstall` 移除本仓库安装的登录项，保留运行目录。再从 `~/.codex/hooks.json` 移除本桥接对应的 Stop 命令。确定不再需要历史数据后，可以自行归档或删除旧目录，并在飞书后台停用应用或轮换凭据。

## 切换聊天的卡片行为

点击管理卡的「切换聊天」后，原管理卡保留，列表另发一条消息；选中后的确认和翻页也另发。管理卡的「切换聊天 / 当前聊天」可重复使用，不受本地十分钟期限限制（仍受飞书平台交互有效期约束）。列表选项十分钟内有效且只能处理一次，过期后重新打开列表。新建提交、审批与任务投递继续保留原防重规则。

发送失败会尽力另发文字提示；可重新点管理入口，或发送「切换聊天」。若提示已切换但确认发送失败，发送「当前聊天」核对。重复回调和正在处理的同一按钮不会并发重复发送；进程重启后导航可以重新打开。

## 在飞书回答 Codex 的中途提问

初始化时添加 `--questions --metadata-db /绝对路径/state.sqlite`；现有安装在私密 `service.json` 中设置 `questionsEnabled: true`，保留有效的 `chatMetadataDatabase` 后重启连接。关闭该开关并重启即可停止捕获和回答。该开关独立于最终回复汇报，范围是本机未归档主聊天启用后的新异步提问；不补发历史，也不采集推理或其他工具内容。

Codex 调用 `request_user_input_async` 时，每个问题发一张飞书卡片。点击选项，或照卡片格式发送 `回答 问题编号 题号 你的答案`，最多2000字。多题需全部回答后一起送回**提出问题的那个聊天**，不会改变全局当前聊天。问题30分钟内有效，过期、归档、暂停后恢复、重复选择均会明确拒绝。断线或入队结果未知不会自动重投。

“答案已加入原聊天”仅代表通过 Codex 的 `queue` 接口提交；原聊天实际消费和后续回复是下一步证据。飞书作答后，桌面原生问题框仍会保留，不会自动关闭：当前实现只把答案作为用户消息加入原聊天，没有提交原生答题状态。无需再为同一答案在桌面重复提交。若检测到桌面已经提交本组任一道题，整组飞书卡停止接受答案，其余题目请在桌面完成。同步阻塞的 `request_user_input` 尚未接入，仍需在桌面回答；本功能不批准工具权限。

当前发现问题依赖本机只读 SQLite 索引和增量聊天记录，属于需要随 Codex 版本验证的适配。记录格式或来源无法核实会拒绝捕获，并写入脱敏诊断。日志事件 `question_scan_observed`、`question_card_sent`、`question_answer_delivery` 分别对应发现、发卡与答案入队；它们不记录问题/答案正文。首次扫描长聊天会分批追赶，正常轮询间隔2秒。
