# 发布维护

1. 从当前提交做一次干净检出，运行 `npm ci`、`npm run check`、`npm test`。修改图表功能时运行真实 Chrome 测试。
2. 核对 `git ls-files` 和新仓库历史。公开内容应只包含源码、示例、依赖锁文件、测试和文档。检查凭据、旧聊天 ID、个人目录、聊天内容、日志和私密数据是否误入。
3. 更新版本和 [CHANGELOG](../CHANGELOG.md)。Git 使用不带 `v` 的语义版本标签，例如 `0.1.0`。
4. 创建 GitHub 仓库后再配置远程。首次公开前核对仓库所有者、许可证与 README，开启私下漏洞报告。发布时从实际验证记录写已验证范围和兼容限制。
5. 从另一个目录按用户指南验证安装和启停。用独立飞书机器人和测试聊天完成真实往返后，再更新对应版本的兼容说明。
