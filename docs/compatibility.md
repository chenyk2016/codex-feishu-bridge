# 兼容性

## 运行要求

| 项目 | 要求 |
| --- | --- |
| 系统 | macOS；安装器使用用户级登录服务 |
| 运行时 | Node.js 24+、macOS 系统 Python 3 |
| Codex | 桌面环境及匹配的 CLI，支持 `queue --thread --message`；回复汇报需要 Stop Hook |
| 飞书 | 企业自建应用机器人，配置消息和卡片长连接订阅 |
| Mermaid | 开启图片功能，安装本机 Google Chrome |
| 元数据功能 | 全主聊天汇报、最近回复和异步问答需要当前客户端的本机 SQLite 索引 |

Windows/Linux 和国际版 Lark 暂未支持。Codex 的元数据与聊天记录格式可能随版本变化，升级后应重新检查收发和问答。

## 验证范围

0.2.0 已在维护者的 Mac 上验证消息往返、图片、异步选项问答、聊天创建和暂停恢复。独立新机器、新飞书应用从零安装的完整往返尚未验证。手机端新的另发列表交互仍待单独确认。

自动测试覆盖路由、配对、去重和异常处理；运行方法见[贡献指南](../CONTRIBUTING.md)。

## 已知限制

- 飞书作答不会关闭桌面原生问题框；同步阻塞提问和普通工具审批仍在桌面处理。
- Mac 休眠、断网或关机时无法正常收发；完整退出 Codex 后的自动唤起尚未验证。
- 桌面与飞书同时答题可能发生竞争，避免两端重复提交。
- 结果未知时不自动重投。先核对原聊天，再决定是否重新发送。

升级后用一条无敏感内容的任务确认：飞书发送 → 原聊天执行 → 回复回到飞书。开启图片、问答或新建功能时，分别检查对应流程。
